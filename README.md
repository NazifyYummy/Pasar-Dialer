## Project Summary (English)

Pasar Dialer is an Android call management application created for a sales unit at a Pasargad Insurance branch. It is designed for Persian users, so don't expect details in English. You can ask AI for more information.

**Why it was built:** Sales agents in that branch where I used to work used to spend about 25 seconds per call searching for phone numbers on other platforms like Divar, Sheypoor, and Torob, writing them down, then copying and dialing. This slowed down daily outreach and wasted working time. With Pasar Dialer, this time is reduced to about 2 seconds per call.

**What it does:** It allows agents to import a prepared database of phone numbers and related information in JSON format. Then they can call contacts with a single tap, track called numbers, mark callbacks, and avoid duplicate calls. Supervisors can also see how many calls each agent made today. For 100 calls, each agent saves about 2300 seconds. Supervisors should evaluate whether this time saving justifies the cost of preparing the database.

**Additional info:** The database can include extra information about the contact (like name, city, job, age, etc.) to help agents personalize the conversation and better persuade the customer.

**Note:** This project is no longer actively developed. For questions, please contact via GitHub.

## راهنمای فارسی

 پروژه حاضر یک اپلیکیشن اندرویدی مدیریت تماس برای یک واحد فروش و بازاریابی تلفنی است که فرآیند تماس‌گیری را از ۲۵ ثانیه به ۲ ثانیه کاهش می‌دهد. این برنامه با استفاده از یک رابط کاربری ساده و یک دیتابیس محلی از شماره‌ها و اطلاعات جانبی، به کارشناسان فروش اجازه می‌دهد تا به سرعت با مخاطبین تماس بگیرند.

> این نرم‌افزار برای یکی از شعب **بیمه پاسارگاد** طراحی و پیاده‌سازی شده است.

## معرفی کلی

کارشناسان فروش آن شعبه در فرآیند بازاریابی تلفنی خود مسیر زیر را طی می‌کردند:

1. جستجوی یک صنف کاری در نرم‌افزارهایی مثل **دیوار**، **شیپور** یا **ترب**
2. پیدا کردن شماره تلفن
3. یادداشت شماره در برگه برای ثبت نتایج
4. کپی شماره و برقراری تماس

این فرآیند **حداقل ۲۵ ثانیه** زمان می‌برد. اما با **Pasar Dialer**، با تهیه یک دیتابیس از شماره تماس‌ها به همراه اطلاعات دیگر (فرمت JSON)، می‌توان این زمان را به **۲ ثانیه** کاهش داد.

علاوه بر این، دیتابیس ورودی می‌تواند شامل **اطلاعات اضافه درباره صاحب شماره تلفن** باشد؛ اطلاعاتی مانند نام کامل، شهر، شغل، سن، کد ملی و هر فیلد دلخواه دیگر. این اطلاعات به کارشناس فروش کمک می‌کند تا قبل از تماس، شناخت اولیه‌ای از مخاطب داشته باشد و مکالمه را شخصی‌سازی کند. شخصی‌سازی مکالمه نقش مؤثری در **متقاعد کردن مشتری** و افزایش نرخ موفقیت تماس‌ها دارد.

| مرحله | فرآیند سنتی | Pasar Dialer |
|---|---|---|
| جستجوی شماره | ۱۵ ثانیه | ۰ ثانیه (از قبل آماده) |
| یادداشت شماره | ۵ ثانیه | ۰ ثانیه |
| کپی کردن یا نوشتن شماره و تماس | ۵ ثانیه | ۱ ثانیه (کلیک روی شماره) |
| زمان برای وارد کردن شماره تلفن ها | ۰ ثانیه | زمان برای وارد کردن اطلاعات تقسیم بر تعداد شماره تلفن ها تقریبا ۱ ثانیه | 
| **جمع** | **۲۵ ثانیه** | **۲ ثانیه** |

**صرفه‌جویی: ۲۳ ثانیه به ازای هر تماس**

### محاسبه برای ۱۰۰ تماس

- فرآیند سنتی: ۱۰۰ × ۲۵ = **۲۵۰۰ ثانیه**
- Pasar Dialer: ۱۰۰ × ۲ = **۲۰۰ ثانیه**
- **صرفه‌جویی: ۱۰۰ × ۲۳ = ۲۳۰۰ ثانیه**

یعنی برای هر کارشناس فروش، به ازای هر ۱۰۰ تماس، **۲۳۰۰ ثانیه (حدود ۳۸ دقیقه و ۲۰ ثانیه)** زمان ذخیره می‌شود.

> **نکته مدیریتی برای سرپرست واحد:** سرپرست واحد می‌تواند بررسی کند که هزینه ۲۳۰۰ ثانیه از عمر هر کارشناس برای هر روز کاری بیشتر است یا هزینه تهیه کردن یک دیتابیس از شماره تلفن‌ها. به عبارت دیگر، آیا صرفه‌جویی زمانی حاصل از این ابزار، سرمایه‌گذاری روی تهیه و به‌روزرسانی دیتابیس را توجیه می‌کند یا خیر.

## قابلیت‌های کلیدی

### مدیریت و پیگیری تماس‌ها
- **تشخیص تماس تکراری**: هنگام لمس شماره، ابزار شماره‌گیر سیستم باز شده و شماره پر می‌شود؛ وضعیت تماس فوراً در دیتابیس ثبت و **به رنگ قرمز** در می‌آید
- **هشدار تماس تکراری**: در صورت لمس مجدد شماره، کادر هشدار امنیتی نمایش داده می‌شود
- **گزینه «بعداً زنگ بزن»**: چک‌باکس برای شماره‌هایی که پاسخگو نبوده‌اند

### داده‌های تکمیلی و شخصی‌سازی مکالمه
- دیتابیس ورودی فقط محدود به شماره تلفن نیست و می‌تواند شامل **هرگونه اطلاعات اضافه درباره صاحب شماره** باشد.
- این اطلاعات به کارشناس فروش کمک می‌کند تا با شناخت بیشتری با مشتری صحبت کند و مکالمه را متناسب با شرایط او هدایت نماید.
- مثال‌هایی از این اطلاعات: نام کامل، شهر، شغل، سن، کد ملی، وضعیت تأهل، علایق و هر فیلد دلخواه دیگر.
- هرچه اطلاعات جانبی دقیق‌تر و کامل‌تر باشد، کارشناس فروش می‌تواند **بهتر مشتری را متقاعد کند** و احتمال موفقیت تماس افزایش می‌یابد.

### نظارت و گزارش‌گیری مدیریتی
- **مشاهده تعداد تماس‌های روزانه هر کارشناس فروش**: سرپرست می‌تواند بررسی کند که هر کارشناس فروش در امروز به چند نفر زنگ زده است.
- **گزارش زنده و دقیق**: آمار تماس‌ها بر اساس تاریخچه ثبت‌شده در دیتابیس محلی، به صورت لحظه‌ای به‌روزرسانی می‌شود.

### دسته‌بندی و فیلتر وضعیت تماس
- **همه**: نمایش کل دیتابیس
- **زنگ نزده**: شماره‌هایی که هنوز تماس گرفته نشده‌اند
- **زنگ زده**: شماره‌هایی که تماس گرفته شده‌اند (به رنگ قرمز)
- **دوباره زنگ بزن**: شماره‌هایی که چک‌باکس تماس مجدد برای آن‌ها تیک خورده است
- **تاریخچه تماس**: ثبت لحظه‌ای تمامی تماس‌ها با تاریخ و ساعت دقیق

### جستجو و فیلتر پیشرفته
- نوار جستجو برای فیلتر فوری شماره‌ها، کدهای ملی، شهرها و سایر اطلاعات

## ساختار داده ورودی (JSON)

داده‌ها **باید به صورت JSON** وارد شوند. برنامه از ساختار زیر پشتیبانی می‌کند:

```json
[
  {
    "number": "09123456789",
    "other_informations": {
      "national_code": "1234567890",
      "city": "تهران",
      "full_name": "احمد رضایی",
      "age": 32
    }
  },
  {
    "number": "09361234567",
    "other_informations": {
      "national_code": "9876543210",
      "city": "اصفهان",
      "full_name": "سارا محمدی",
      "job": "مهندس نرم‌افزار"
    }
  },
  {
    "number": "09107894561",
    "other_informations": {
      "national_code": "4567891230",
      "city": "شیراز",
      "full_name": "علی کریمی"
    }
  },
  {
    "number": "09393456789",
    "other_informations": {
      "national_code": "7891234560",
      "city": "مشهد",
      "full_name": "مریم حسینی",
      "age": 28,
      "job": "پزشک"
    }
  },
  {
    "number": "09121234567",
    "other_informations": {
      "national_code": "3216549870",
      "city": "تبریز",
      "full_name": "رضا صادقی"
    }
  }
]
```

### راهنمای ساختار JSON

- کل ساختار یک **آرایه** از اشیاء است.
- هر شیء حداقل دو کلید اصلی دارد:
  - **`number`**: شماره تلفن مخاطب (به صورت رشته).
  - **`other_informations`**: یک شیء شامل اطلاعات جانبی مخاطب.
- کلیدهای داخل `other_informations` کاملاً **پویا** هستند و می‌توانند هر چیزی باشند:
  - `national_code`، `city`، `full_name`، `age`، `job` و ...
  - حتی می‌توانید کلیدهای دلخواه دیگری اضافه کنید.
- این اطلاعات جانبی می‌تواند به **متقاعد کردن مشتری** کمک کند؛ زیرا کارشناس فروش قبل از تماس، دید کلی‌تری نسبت به مخاطب دارد و می‌تواند مکالمه را شخصی‌سازی کند.
- مقادیر می‌توانند **عدد**، **رشته** (حتی حروف فارسی) یا ترکیبی باشند.
- ممکن است اطلاعات برخی مخاطبین **بیشتر یا کمتر** باشد؛ برنامه به صورت خودکار همه آن‌ها را نمایش می‌دهد.
- در صورت استفاده از سینتکس پایتون (تک‌کوت `'` به جای دبل‌کوت `"` و مقادیری مثل `None`، `True` یا `False`)، یک مبدل هوشمند داخلی آن را قبل از پارس تصحیح می‌کند.

### روش‌های بارگذاری داده
1. **کپی و پیست مستقیم**: یک دکمه برای وارد کردن کدهای JSON در بالای صفحه
2. **انتخاب فایل**: امکان انتخاب فایل‌های `.json` یا `.txt` از حافظه دستگاه
3. **دکمه Paste Sample**: شبیه‌سازی و تست فوری فرمت پایتون با یک کلیک

## راهنمای کاربری

### ۱. وارد کردن داده‌ها
- روی دکمه **«Import JSON»** در بالای صفحه کلیک کنید
- کد JSON خود را کپی و پیست کنید یا فایل را از حافظه انتخاب نمایید
- روی **«ذخیره»** کلیک کنید

### ۲. تماس با مخاطبین
- روی شماره مورد نظر در لیست کلیک کنید
- ابزار شماره‌گیر سیستم باز شده و شماره پر می‌شود
- پس از تماس، شماره **به رنگ قرمز** در می‌آید

### ۳. ثبت تماس مجدد
- اگر شماره پاسخگو نبود، چک‌باکس **«بعداً زنگ بزن»** را تیک بزنید
- این شماره در سربرگ **«دوباره زنگ بزن»** قابل مشاهده است

### ۴. مشاهده تاریخچه
- به سربرگ **«تاریخچه تماس»** بروید
- تمام تماس‌ها با تاریخ، ساعت و ثانیه ثبت شده‌اند
- امکان تماس مجدد یا حذف سابقه وجود دارد

### ۵. نظارت سرپرست
- سرپرست می‌تواند در بخش گزارش‌ها یا تاریخچه تماس، تعداد تماس‌های هر کارشناس فروش را در **امروز** مشاهده کند.
- این آمار به صورت خودکار از روی تماس‌های ثبت‌شده در دیتابیس محلی محاسبه می‌شود.
